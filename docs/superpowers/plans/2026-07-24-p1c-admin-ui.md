# P1c — Admin UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The merchant-facing admin (apps/admin): auth pages, onboarding wizard, catalog management (products/variants/images/categories/CSV), staff, and settings — all in es-CO over the P1a/P1b API — plus the P1 DoD Playwright e2e (signup → wizard → CSV 10 products → launch → live store).

**Architecture:** Next.js 15 App Router. `packages/ui` gains Tailwind 4 + a minimal shadcn-style primitive set (copied-in source components, CSS-variable theming per spec §5.4). The admin app proxies `/api/*` → the NestJS API via Next rewrites so better-auth cookies stay same-origin (no CORS). Client state stays simple: server components where possible, small client components with fetch + form state; no data-fetching library.

**Tech Stack:** Next 15 / React 19 · Tailwind 4 (@tailwindcss/postcss) · shadcn-style components in packages/ui · zod (shared schemas from @ventia/core re-used for client-side validation) · Playwright (chromium preinstalled at /opt/pw-browsers — do NOT run `playwright install`).

## Global Constraints

- All UI copy es-CO Spanish; code/comments/commits English. TypeScript strict. Conventional commits.
- Server-side enforcement already exists — the UI must still render role-aware (staff: catalog only) and handle typed API errors (`PLAN_LIMIT_EXCEEDED` → upgrade prompt, `VALIDATION_FAILED` → field errors, `FORBIDDEN_ROLE`/`TENANT_SUSPENDED` → friendly notices).
- API access ONLY through the same-origin proxy path `/api/...` (rewrite → `API_INTERNAL_URL`); never hardcode api hosts in client code.
- Testing: vitest for lib logic (fetch client, error mapping, form helpers); the heavy UI behavior is covered by the Task-8 Playwright e2e (component-level rendering harness explicitly deferred — recorded decision). Baseline suites (api 135, db 16, core 17, storefront 2) stay green.
- Playwright e2e runs locally in P1c (CI e2e integration deferred to P6 hardening — recorded decision).
- Git identity before commits: `git config user.email noreply@anthropic.com && git config user.name Claude`.

### Task 1: UI foundation — Tailwind 4 + primitives + admin shell plumbing

**Files:** `packages/ui` (tailwind preset css, `cn` util, primitives: Button, Input, Label, Card, Dialog, Select, Table, Badge, Alert, Spinner, FormField wrapper); `apps/admin` (tailwind/postcss wiring, globals.css importing the ui preset, next.config.ts rewrites `/api/:path*` → `${API_INTERNAL_URL}/:path*`, `lib/api.ts` typed fetch client, `lib/errors.ts` error mapping, root layout with es-CO html lang + font).
**Interfaces:** `apiFetch<T>(path, init?): Promise<T>` throwing `ApiError { status, code, details }` parsed from `{ error, details }` bodies; primitives exported from `@ventia/ui`; `API_INTERNAL_URL` env (default http://localhost:4000).
**Tests:** vitest in apps/admin for `lib/errors.ts` mapping (`PLAN_LIMIT_EXCEEDED` → upgrade message es-CO; `VALIDATION_FAILED` flatten → field map) and `apiFetch` (mock fetch: ok json, error body, network error).
Steps: RED (lib tests) → implement → `pnpm build && pnpm typecheck` green → commit `feat: add ui primitives and admin app foundation`.
